# Supported browser application capture

Implement alongside the approved recruiting plan. Preserve existing email capture. Recruiters create a candidate/job-linked intent before opening the external form; started is a draft, never Applied. Optional Chrome/Edge MV3 extension pairs through a short-lived one-time portal code, receiving a revocable scoped credential kept in extension local storage. It accesses only user-permitted Greenhouse/Ashby hosts and never captures field values, passwords, cookies or resume contents.

Maintain tab/intent context. Adapters observe known application forms, final submit attempts, application-specific success messages and explicit validation errors. Persist deduplicated events with event/ingestion times and attempt numbers. Server checks credential, active staff, candidate/job/intent ownership, allowed site and evidence. Unknown/ambiguous observations require review; missing events never imply failure. Late errors cannot downgrade submitted/confirmed. Recruiter attestation supplies a fallback, clearly labeled manual evidence. External success observation is distinct from a verified email receipt.

Connect matching email confirmations to unambiguous intents and one submission, preserving receipt-first operation. Capture overview exposes compact candidate/job/status/details and a review action. Tests cover token expiry/revocation, event replay, candidate/tab separation, failed retry and receipt-first confirmation. Document supported selectors/templates and limitations; no promise of universal portal support. No automated final submission, extension installation, live database mutation or publication occurs during implementation.
